# VocabFlow 路线图

编写日期：2026-10-30。这是**建议的顺序，不是已承诺的需求**；范围、先后和取舍都由产品负责人（用户）决定。当前代码和已知问题以 `HANDOFF.md` 为准，本文只记录“接下来做什么”。

产品链路：记录 → 补充学习内容 → 学习 → 练习 → 评估 → 更新掌握度 → 安排复习 → 复习。目前完成了前三段中的“记录”“补充”（假数据）和“学习”的展示部分。

## 已完成

| 里程碑 | 内容 |
| --- | --- |
| M1 | 身份（注册、登录、登出、token 撤销）与词汇后端：个人词库、共享词条、确定性的假补全 |
| M2 | 每日计划后端：每用户每天一份持久化计划，从 `NEW` 词汇最早优先选取，复习项接口已留（目前恒为空） |
| M3 | 前端：认证与会话恢复、词汇界面（添加、分页列表、详情）、今日计划页、统一 401 处理 |

## 建议的后续里程碑

### M4：加固（最先做，小而紧）

目标：补齐已发现的缺口，让后续大功能建在稳的底座上。

- **持续集成**：加 GitHub Actions，跑后端 `./mvnw verify`（需要 Docker）和前端 lint、typecheck、test、build。目前仓库没有 `.github/`，全靠手动跑，这是性价比最高的一项。
- **后端认证（需要单独授权，因为改认证契约）**：安全过滤器统一确认 token 对应的用户仍存在，不存在就返回 401。目前该情形下 `/me` 与每日计划返回 401，词汇列表返回 200，添加词汇返回 500。
- **前端小修**：词汇页页码放进 URL、注册成功后清掉“已登出”标记、从今日计划进入详情后返回今日计划、午夜后日期自动更新，这四项已完成。还剩：跨标签页登出同步；`localStorage` 读写失败的处理。
- **测试补充**：键盘操作与读屏检查；是否支持暗色模式（先定再做）。

需要决定：现在是否修认证；暗色模式做不做。

### M5：真实补全（AI 或字典）

目标：用真实内容取代确定性的假补全。

- 后端：接入真实提供方（适配器接口已有）；补全改为可重试的异步流程；`FAILED` 词条的重试入口；记录内容来源；用“领取标记”避免并发时重复调用（需新增 Flyway V5 迁移，并把 `MysqlFlywayIT` 的迁移数量断言由 4 改为 5）；密钥只走环境变量；限流和成本上限。
- 前端：详情页重试按钮；PENDING 轮询；失败文案。
- 风险：第一个带真实成本和外部依赖的里程碑，先小范围试点。

需要决定：用哪家 AI 或字典；预算上限；内容质量标准。

### M6：学习闭环

目标：让今日计划真正能学，而不只是展示。

- 用户时区：进后端设置，还是继续由前端传本地日期。
- 学习状态流转（`NEW → LEARNING → FAMILIAR → MASTERED`），计划项可标记完成，避免同一个词在不同日期反复进计划。
- 练习：先做最简单的一种（如闪卡或选择题），再扩展。
- 计划语义：是否不保存空计划（目前当天的空计划会被“冻结”）。

需要决定：练习形式；状态怎么流转；空计划的处理。

### M7：复习与掌握度

目标：间隔复习，是产品的核心价值，也最需要设计，建议先出方案再动手。

- 真实的 `DueReviewProvider`，把到期的词放进计划的 `reviewItems`。
- 评估与掌握度模型，选定调度算法。
- 前端复习界面。

依赖 M6 的学习状态。

### M8：上线准备

目标：能真正给用户使用。

- 部署：前端静态托管的回退路由、同源 API 转发或 CORS、环境配置、数据库备份。
- 认证加固：评估用 HttpOnly cookie 取代 `localStorage`；token 加随机数；`revoked_tokens` 过期清理；是否加刷新机制。
- 运维：日志、监控、错误追踪。
- 体验与合规：隐私说明、错误页、空状态打磨。

需要决定：部署到哪里；域名；预算。

## 暂未排期的功能

词汇的搜索、排序、编辑、删除（后端目前没有）；导入导出；学习统计面板；PWA 或移动端；界面多语言（目前全英文）。

读音：**浏览器朗读（Web Speech API）已完成**，词汇列表、详情页和今日计划都有播放按钮，会优先选美式声音，但具体音质和口音取决于用户设备，没有存储的录音。要统一音质和口音，需要服务端语音合成并保存音频，建议并入 M5（和真实补全共用来源记录、密钥、限流和成本上限这套基础设施）。M6 的练习如果要“先听后选”，需要设计成用户先有一次点击，因为浏览器不允许无手势自动出声。

## 顺序与依赖

- M4 最先做：后续每一步都靠 CI 兜底。
- M5 之前先确定 AI 或字典提供方。
- M7 依赖 M6 的学习状态；M8 可在 M5 之后与 M6 并行准备。

## 每个里程碑的完成标准

- 相关门禁全部通过：后端 `spotless:check`、`test`、`verify`；前端 lint、typecheck、test、build。
- 关键流程在真实浏览器里验证过，并如实记录没有验证的部分。
- `README.md`、`HANDOFF.md`（必要时 `CLAUDE.md`）同步更新。
- 单独提交，不混入无关改动。

## 并行与协作

前后端互不依赖的任务可以并行；会改同一批文件的（例如都改前端路由和应用外壳）不要并行，必要时用独立 worktree，合并由用户决定。可复用的子代理角色见 `.claude/agents/` 和 `HANDOFF.md` 第 10 节。

## 仍待用户确认的产品问题

目标用户画像（是否只服务 CLB 与加拿大学习者）、商业模式、是否做移动端。这些会影响 M6 之后的取舍。
