# VocabFlow 路线图

编写日期：2026-10-30，2026-11-01 更新了“已完成”和“暂未排期”。这是**建议的顺序，不是已承诺的需求**；范围、先后和取舍都由产品负责人（用户）决定。当前代码和已知问题以 `HANDOFF.md` 为准，本文只记录“接下来做什么”。

产品链路：记录 → 补充学习内容 → 学习 → 练习 → 评估 → 更新掌握度 → 安排复习 → 复习。目前已完成：记录、补充学习内容（可用真实模型）、学习和间隔复习；“练习”只有一种，即用当天学过的词写成的阅读短文；评估和更细的掌握度模型还没有。

## 已完成

| 里程碑 | 内容 |

| M2 | 每日计划后端：每用户每天一份持久化计划，从 `NEW` 词汇最早优先选取，复习项接口已留（目前恒为空） |
| M3 | 前端：认证与会话恢复、词汇界面（添加、分页列表、详情）、今日计划页、统一 401 处理 |

## 建议的后续里程碑

### M4：加固（最先做，小而紧）

目标：补齐已发现的缺口，让后续大功能建在稳的底座上。

- **持续集成**：工作流文件 `.github/workflows/ci.yml` 已加入并合并（后端 `spotless:check` 和 `verify`，前端 lint、typecheck、test、build），已在 GitHub 上运行成功两次，Action 已升到 `@v5`。分支保护已开启（`Protect main` 规则集，必需检查 `backend`、`frontend`）。
- **后端认证（已完成）**：安全过滤器现在确认 token 对应的用户仍存在，不存在就统一返回 401（此前词汇列表返回 200、添加词汇返回 500）。每个带 token 的请求多一次按主键的查询。
- **前端小修**：词汇页页码放进 URL、注册成功后清掉“已登出”标记、从今日计划进入详情后返回今日计划、午夜后日期自动更新，这四项已完成；跨标签页登录/登出同步和 `localStorage` 读写失败的处理也已完成（存储不可用时只能在当前标签页内存里保持登录，无法跨标签同步）。
- **键盘与读屏（部分完成）**：已用真实浏览器的纯键盘走查修了焦点丢失、页面标题、跳转链接、表单错误关联、添加成功提示和一处对比度。用户已用 VoiceOver 听过，反馈没问题；每个页面另有 axe-core 自动测试。2026-10-30 在真实浏览器里扫过全部页面和状态的颜色对比度（含悬停和跳转链接焦点），修了一处悬停时 4.43:1 的文字。还没做：NVDA 等其他读屏软件；缩放/高对比度；注册页下拉框的键盘操作。
- **暗色模式（已决定：暂不做）**：界面只有浅色，写死了约 172 处浅色类名（14 个文件）。已声明 `color-scheme: light`，系统是暗色时浏览器自带的控件和滚动条也保持浅色，与页面一致。等界面稳定后再做的话，倾向“跟随系统设置”（Tailwind 的 `dark:` 变体，不加切换按钮），并且要把已修的对比度整套按暗色重测一遍。

需要决定：现在是否修认证。

### M5：真实补全（AI 或字典）

目标：用真实内容取代确定性的假补全。

- 后端（**已完成，分支 `real-enrichment-backend`**）：Claude 适配器（`claude-haiku-5-5`，思考关闭，JSON Schema 约束加服务端校验）；后台异步补全；`FAILED` 词条的手动重试接口；来源、时间、次数记录；用领取标记避免并发重复调用；密钥只走环境变量；每用户每日次数上限和请求超时（V5 迁移）。已用真实密钥手动试过少量词，内容固定面向约 CLB 5–7，**已决定不按用户级别区分**（产品负责人，2026-10-30）：所有用户共用同一份内容。
- 前端（**已完成**）：PENDING/PROCESSING 轮询（3 秒，最多 2 分钟）；详情页状态面板、重试按钮；失败文案和超限提示。
- 风险：第一个带真实成本和外部依赖的里程碑，先小范围试点。

已决定（2026-10-31）：用 Claude：词条补全用 `claude-haiku-5-5`，阅读短文用 `claude-sonnet-5-5`；预算靠每天的调用次数上限（默认 50，两者共用）；内容质量靠人工用 `scripts/try_*_prompt.py` 试跑后判断。

### M6：学习闭环与间隔复习（原 M6、M7 合并）

目标：让今日计划真正能学。用户决定采用类似 Anki 的算法，所以这两个里程碑合并做。

- 后端（**已完成，分支 `spaced-repetition-backend`**）：Anki 式 SM-2、学习队列、评分接口、复习记录、到期复习进入计划、不保存空计划（V6 迁移）。
- 前端（**已完成**）：学习页 `/app/study`、四个评分按钮和下次时间。记忆效果要靠实际使用几周来判断。
- 已决定：闪卡自评；CLB 级别保留不动；时区继续由前端传本地日期；不做撤销、牌组、自定义参数界面。以后可用 `review_logs` 评估是否换 FSRS。

### 学习体验：以学习为中心

目标：登录就开始当天学习（用户 2026-10-31 提出）。

- 已完成：计划自动补词和当天结束状态、再学一批、学习页成为首页（进度、完成页），Today 页去掉。
- Settings 页、词汇列表筛选界面已完成。进度条按用户的模型做：已学、学习中、未学三段，加起来等于总数。

### M8：上线准备

目标：能真正给用户使用。用户决定先只在本机和局域网运行，给自己和少数亲友用。

- 已完成：Docker Compose 一键启动、邀请码、CSP 和安全响应头、备份恢复脚本、健康检查。token 继续放 `localStorage`。
- 上公网前必须做：HTTPS 和域名、服务器、登录频率限制。
- 面向更多人时再做：`revoked_tokens` 过期清理、token 加随机数、找回密码、邮箱验证、隐私说明、删除账号、监控和错误追踪、异地备份。

## 暂未排期的功能

词汇的搜索、排序、编辑，以及删除已完成的词（目前只能删补全失败的词）；导入导出；学习统计面板；离线和 service worker（现在只有 iPhone 主屏幕图标，不支持离线）；界面多语言（目前全英文）。

阅读短文的后续可能：删除或重新生成、指定主题、更多篇数、历史统计。拼错检测的后续可能：“保持原样”的出口，对乱敲的输入给出提示。原形的显示方式（现在是“保留原词，标注原形”，用户觉得别扭但决定先不改）可以改成“直接变成原形”，需要处理合并和计划里的引用。构建加速：给后端镜像加 Maven 缓存挂载（用户说下次再提）。

读音：**浏览器朗读（Web Speech API）已完成**，词汇列表、详情页和学习卡片都有播放按钮，设置里可分别选“卡片出现时读”和“点 Show answer 时读”，阅读短文可以整篇朗读；会优先选美式声音，但具体音质和口音取决于用户设备，没有存储的录音。**已决定保持现状，不做服务端语音合成**（产品负责人，2026-10-30）。浏览器不允许无手势自动出声，所以读单词必须放在按“Show answer”的同一次点击里；以后“先听后选”这类练习也要设计成用户先有一次点击。

## 顺序与依赖

- M4 最先做：后续每一步都靠 CI 兜底。
- M5 之前先确定 AI 或字典提供方。
- M8 可与 M6 并行准备。

## 每个里程碑的完成标准

- 相关门禁全部通过：后端 `spotless:check`、`test`、`verify`；前端 lint、typecheck、test、build。
- 关键流程在真实浏览器里验证过，并如实记录没有验证的部分。
- `README.md`、`HANDOFF.md`（必要时 `CLAUDE.md`）同步更新。
- 单独提交，不混入无关改动。

## 并行与协作

前后端互不依赖的任务可以并行；会改同一批文件的（例如都改前端路由和应用外壳）不要并行，必要时用独立 worktree，合并由用户决定。可复用的子代理角色见 `.claude/agents/` 和 `HANDOFF.md` 第 10 节。

## 仍待用户确认的产品问题

目标用户画像（是否只服务 CLB 与加拿大学习者）、商业模式、是否做移动端。这些会影响 M6 之后的取舍。
